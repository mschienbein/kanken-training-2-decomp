## Proposed U1 rule

All conditions are mandatory; missing, contradictory or unsupported evidence fails closed.

1. The complete allocated section is readonly executable `SHT_PROGBITS`, non-NOBITS, not link-ordered, with complete candidate bytes and an entry at offset zero. It defines exactly one nonzero-sized `STT_FUNC`, an ARM Itanium-ABI `D0Ev` deleting destructor under the ARMCC split-section name `i.<symbol>`. The accepted class encoding is a sequence of length-checked ordinary identifiers (simple or namespace/nested-class names); template/substitution/thunk/other encodings are not inferred. Only local section symbols and valid local ARM/Thumb/data mapping markers may accompany it. A trailing owned literal pool is permitted. D1/D2 and C1/C2 are not eligible: a zero-sized D2/C2 is a same-section identity alias, not a separately dead wrapper, and the shared section may supply a bound D1/C1 body.
2. No symbol in the section has a canonical names binding, proposed overlay binding, explicit per-link binding, or catalogued name/entry identity. Bound D0 bodies retain the ordinary placement/comparison path; U1 cannot remove them. All supplied COMDAT copies are checked, and every allocated member of every affected group/copy must have its own U1 or already-proved v8 removal proof. Unknown group flags, retained/live or unrepresented members and contradictory copies fail closed. Entry/KEEP/export/used/uninterpreted retention metadata always prevents U1.
3. For the same encoded class and defining object, an emitted retained D1 entry has an explicit binding to a catalogued function start. The corresponding `_ZTV` symbol has an explicit original-image binding outside catalogued code and BSS. At that primary table, the offset-to-top is zero; RTTI is null or agrees with an explicitly bound `_ZTI`; the first virtual slot at `_ZTV + 8` agrees with the bound D1 including its ISA bit, and the deleting-destructor slot at `_ZTV + 12` is null. Missing, unreadable, misaligned, overlapping or contradictory witnesses fail closed. This supports only the destructor-first primary-table layout, not arbitrary slots or secondary tables. Proposed bindings remain reviewable evidence, not autonomous authority about class identity.
4. An otherwise independently eligible U1 D0 may own eliminated unwind data under the same structural and whole-group/copy discipline as v8's removed R1 helpers. Its readonly allocated `SHT_ARM_EXIDX` has `SHF_LINK_ORDER` and `sh_link` to that exact D0 section, is exactly one eight-byte entry, and has exactly one zero-effective-addend entry-key `R_ARM_PREL31`. The second word is CANTUNWIND, an inline personality-0 compact entry, or a PREL31 to the beginning of one exclusive readonly frame-only compact extab. Out-of-line personalities 0/1/2 require the complete encoded unwind prefix and exactly one final zero descriptor-list terminator. Only the matching undefined `__aeabi_unwind_cpp_pr0/1/2` NONE dependency is understood. Roots, original bindings, independently named entities, wrong ownership, combined/shared/interior/truncated/nonempty-descriptor metadata and unsupported relocations/dependencies refuse removal.
   The exemption is edge-specific: an exidx's exact `SHF_LINK_ORDER` link and offset-zero PREL31 entry key may name only its own removed owner, and its optional structural PREL31 tail may reach only its own exclusive extab. Extab is reached only by that own index. The already specified exact undefined ABI-personality NONE marker is not a supplied-section edge; it remains supported, not a license to reference another supplied definition.
   Every other section edge from a companion refuses, whether through INFO_LINK, relocation or LINK_ORDER and whether its destination is kept, unplaced, a peer D0, another removal candidate or a foreign section. Nonzero INFO_LINK is nonstructural even when it names the same owner as the valid index link; an INFO_LINK flag with zero info has no edge. No self/peer cycle is inferred dead, including cycles through companions or corresponding COMDAT copies.
5. Before any own-companion exemption, every allocated member of every affected group/copy must be independently eligible R1/U1 code or a validated own-unwind companion, and every outgoing companion edge must pass condition 4's exact structural whitelist. Unsupported group flags, retained/live/unrepresented members and contradictory copies fail closed. Exidx has no other incoming reference; extab's only incoming reference is its own exidx's structural PREL31. After these and existing R1 rules pass, no remaining allocated relocation or link/info dependency may reference D0 or an eliminated companion. Check placed and unplaced code/data/tables, aliases, foreign exidx/extab, dependency markers and unresolved names. Self- and peer-U1 references remain conservative refusals; matching metadata, group normalization and companion membership never prove a dead cycle. V4BX is nonreferencing only in ordinary code. U1 never erases an emitted vtable reference, another function's unwind entry or shared/merged unwind data.
6. Every elimination records `rule: unused_deleting_destructor`, `target: null`, symbols, complete section size/index/name, defining object and the original table/D1 witness metadata in `linker_rewrites`/`linker_section_rewrites` and `removed_special_members`. Each own-exidx/extab is separately identified in that action's `unwind_sections` list by name/index, kind, size and defining object, as v8 reports its companions. No private original/candidate payload is serialized. Source, object, image, names/overlay, catalogue, profile and harness hashes bind every eliminated section. Surviving code/data comparisons and unique emitted ownership remain mandatory.
7. V13 retains zero-sized allocated sections as separate census witnesses, with every relocation, link/info dependency, symbol/root, group membership and defining-object identity preserved across object combination. They do not acquire output placement. A retained or unplaced zero-sized source is not evidence of deadness: any dependency to D0/exidx/extab vetoes removal, and an affected group's unproved zero-sized member vetoes whole-group removal. `SHF_INFO_LINK` dependencies participate alongside `SHF_LINK_ORDER` in the U1, R1 and own-unwind censuses; collecting an edge does not authorize exempting its source. Only independently proved removals and exact condition-4 structural edges may be excluded. Earlier models, including v12, continue to use their recorded census/placement rules.
   An early U1 census precedes placement inference and a final census follows actual R1 removal proofs; neither provisional candidates nor preflight success publish an elimination action.
8. D0 mapping symbols must be local zero-size STT_NOTYPE ARM ABI markers, exactly represented by the section mapping. ARM starts/ranges are four-byte aligned, Thumb starts/ranges two-byte aligned, and all ranges are ordered, nonempty and bounded; the entry marker agrees with ISA. Malformed marker alignment or incomplete code ranges fail closed. COMDAT D0 copies require identical complete section metadata/bytes/mapping, defined-symbol metadata and relocation identities, including normalized target definition/section ownership, binding, kind/value/size. Equal local spellings in different ordinary sections never prove equal targets, even when bytes happen to agree; unresolved distinct/local target identity fails closed.
   Function extents also respect entry-ISA alignment. Every affected allocated group copy has the same independently proved code/own-companion roles, complete metadata and companion contents; role normalization is permitted only for already-validated structural own-companion targets, never arbitrary local or COMDAT destinations.
   V13 preserves and compares the complete semantic section header: resolved name, type, full unmasked `sh_flags`, address, size, raw alignment, entry size, `sh_link`/`sh_info` semantics and actual group membership. File offsets and string-table indices are physical serialization details, not semantic identities. Section-index links are remapped through object combination and may normalize only through independently proved structural roles, after every companion edge passes condition 4. Nonzero unmodeled link/info fields, unavailable metadata, unrepresented targets and inconsistent decoded/raw metadata refuse; metadata is never reconstructed from a reduced boolean subset.
   Each containing group's complete header flags/name/address/size/alignment/entry size and normalized canonical-symbol-table/signature metadata also agree. Missing/duplicate memberships, disagreement with `SHF_GROUP`, an unsupported group/signature/table and unequal group-member role closure refuse. These checks cover every selected COMDAT code copy and own exidx/extab, including pure R1 groups without a U1 owner. Identical metadata is a consistency control, not a waiver of independent eligibility, retention, reference or format checks.
9. V13 matcher evidence binds canonical names and proposed overlay, canonical and proposed profile inputs plus the effective profile, selected models, catalogue, image/exheader layout, toolchain lock/compiler, complete source/object/dependency-header hashes and all decision/reporting harness modules. Compiler-grid results retain each source/pair's section actions, removed identities/companions and equivalent input closure; distinct sources must not overwrite one another's bound objects. Collection refuses U1 models until it has a corresponding action receipt. No consumer may publish a successful U1 comparison while silently dropping its actions. No raw payload is serialized.

## Evidence qualification

[INFERENCE] A null deleting-destructor cell with a separately bound retained D1 is consistent with armlink virtual-function elimination followed by unused-section removal. It does not prove the original linker options, that a same-body D0 exists nowhere else in the sectionless image, or historical class spelling. U1 therefore additionally requires no supplied live reference and no known original identity/binding; it never searches for similar bytes or uses null cells as permission to delete live references. Reviewers must validate the class/table binding against constructor-installed address points and actual virtual-call consumers, then inspect every eliminated section and all reference/group/root exclusions. ARM ABI destructor mangling identifies the D0 role, not source provenance. No native armlink execution is available or claimed.
