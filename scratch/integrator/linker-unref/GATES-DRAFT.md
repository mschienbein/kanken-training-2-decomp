# DRAFT — proposed GATES v1.20: unreferenced deleting destructors

Not adopted. `docs/GATES.md` remains frozen v1.19. This text and implementation require independent exact-text and implementation review before the integrator records a revision and before any checkpoint selects the new model. No in-flight selection or historical receipt may be rewritten.

## Proposed revision entry

**v1.20 (DRAFT, 2026-10-20):** only the explicitly selected immutable model `armlink5-inline-branchnop-v9` adds U1, elimination of an independently unreferenced compiler-generated deleting-destructor section. V9 composes the adopted v8 baseline (including all v6 identity, binding, CFG and original-equality rules) with U1 only. All existing models retain their rules and defaults; v5/v7 stay retired. U1 is not virtual-function elimination, general dead-code elimination, a new exception-table exemption, or evidence of historical source identity. No removed entity earns function/data/denominator credit.

## Proposed U1 rule

All conditions are mandatory; missing, contradictory or unsupported evidence fails closed.

1. The complete allocated section is readonly executable `SHT_PROGBITS`, non-NOBITS, not link-ordered, with complete candidate bytes and an entry at offset zero. It defines exactly one nonzero-sized `STT_FUNC`, an ARM Itanium-ABI `D0Ev` deleting destructor under the ARMCC split-section name `i.<symbol>`. The accepted class encoding is a sequence of length-checked ordinary identifiers (simple or namespace/nested-class names); template/substitution/thunk/other encodings are not inferred. Only local section symbols and valid local ARM/Thumb/data mapping markers may accompany it. A trailing owned literal pool is permitted. D1/D2 and C1/C2 are not eligible: a zero-sized D2/C2 is a same-section identity alias, not a separately dead wrapper, and the shared section may supply a bound D1/C1 body.
2. No symbol in the section has a canonical names binding, proposed overlay binding, explicit per-link binding, or catalogued name/entry identity. Bound D0 bodies retain the ordinary placement/comparison path; U1 cannot remove them. All supplied COMDAT copies are checked, and every allocated member of every affected group/copy must have its own U1 or already-proved v8 removal proof. Unknown group flags, retained/live or unrepresented members and contradictory copies fail closed. Entry/KEEP/export/used/uninterpreted retention metadata always prevents U1.
3. For the same encoded class and defining object, an emitted retained D1 entry has an explicit binding to a catalogued function start. The corresponding `_ZTV` symbol has an explicit original-image binding outside catalogued code and BSS. At that primary table, the offset-to-top is zero; RTTI is null or agrees with an explicitly bound `_ZTI`; the first virtual slot at `_ZTV + 8` agrees with the bound D1 including its ISA bit, and the deleting-destructor slot at `_ZTV + 12` is null. Missing, unreadable, misaligned, overlapping or contradictory witnesses fail closed. This supports only the destructor-first primary-table layout, not arbitrary slots or secondary tables. Proposed bindings remain reviewable evidence, not autonomous authority about class identity.
4. After existing R1/v8 removals have actually passed all their checks, no relocation from any other supplied allocated section may reference the U1 section or any symbol/alias naming it, including unplaced code, data, tables, exidx/extab, `R_ARM_NONE` dependency markers and unresolved-name references to a supplied definition. No `SHF_LINK_ORDER` dependency may retain it. U1 does not erase a referring table cell or a destructor's own exidx. A self-reference or a reference from another U1 candidate is conservatively refused; no dead cycles are inferred. A proven removed R1 section/own-unwind companion is no longer a live source. V4BX remains a nonreferencing marker in ordinary code, never an exemption in unwind data.
5. Every elimination records `rule: unused_deleting_destructor`, `target: null`, symbols, complete section size/index/name, defining object and the original table/D1 witness metadata in `linker_rewrites`/`linker_section_rewrites` and `removed_special_members`. No private original/candidate payload is serialized. The normal source, object, image, names/overlay, catalogue, profile and harness hashes bind the action. Surviving code/data comparisons and unique emitted ownership remain mandatory.

## Evidence qualification

[INFERENCE] A null deleting-destructor cell with a separately bound retained D1 is consistent with armlink virtual-function elimination followed by unused-section removal. It does not prove the original linker options, that a same-body D0 exists nowhere else in the sectionless image, or historical class spelling. U1 therefore additionally requires no supplied live reference and no known original identity/binding; it never searches for similar bytes or uses null cells as permission to delete live references. Reviewers must validate the class/table binding against constructor-installed address points and actual virtual-call consumers, then inspect every eliminated section and all reference/group/root exclusions. ARM ABI destructor mangling identifies the D0 role, not source provenance. No native armlink execution is available or claimed.

## Selection, closure and transition review

V9 extends **v8**, not v6: it retains the already adopted complete R1 own-unwind closure, avoiding a model that silently loses cmodels2's v8 behavior. U1 remains independent of that exception: an exidx reference to D0 is live and refuses U1. A transition from c009-r4/c010/c011's v6 also selects v8's independently reviewed behavior and must re-derive affected R1 callers; a transition from cmodels2's v8 retains that baseline and adds U1. Existing checkpoint selections are immutable and do not inherit v9.

Selection, both fresh full receipts, prepare and history must explicitly bind v9 and every U1 action, including zero-credit owning units. `model_uses` exposes all U1 owning units and their actions. On a model transition, reopen all current R1 callers, existing L1 owning-unit functions, and conservatively every credited function in each U1-owning unit (`U1` review rule); no recovered per-function dependence on a discarded section is claimed. Revised U1 owners already trigger ordinary revised-unit review. Full source/header/object closure and independent per-action manual review remain required, including helper-only U1 owners with no credited row. Byte equality grants no credit to the discarded section.

The integrator must freeze the independently approved exact text as a new revision only after currently active frozen checkpoints close, and before preparing the first checkpoint selecting v9. Implementation availability, focused tests and private matcher receipts are not adoption.
